# 外盘涨跌统计（网页版）

一个看外盘期货涨跌的静态网页：打开就能看到 **25 行品种**的实时涨跌幅（22 个商品 + 3 个美股指数），手机、电脑都适配。另有「上证指数」临时行，只在商品开盘前的两个窗口出现。

**点任意品种名**，新标签页直接打开该品种的**全屏 K 线**（新浪原版页面，可悬停读价、切周期、切指标），省掉在新浪页再点一次「全屏查看」。

**在线地址：<https://wingtrade.github.io/futures-calc/>**

---

## 设计思路

### ① 数据分两类：起始价走云端，最新价走浏览器

**起始价**由 GitHub Actions 按节点定时抓取（商品 10:15 / 11:30 / 15:00 / 23:00 / 01:00 / 02:30 收盘节点 + 美股日线），写成 `data.json`；**最新价**则在打开网页后由浏览器直接向行情源要，15 秒刷新一次。涨跌幅 = 最新价 − 起始价，在浏览器本地计算。

为什么这么分：GitHub Pages 只是静态托管（没有后端服务器），好在行情源都开放 HTTP 接口，浏览器可以直接取——这就绕开了服务器成本，整套系统纯免费运行。美股 3 指数为收盘口径（最近两根日线收盘对比），全天固定、不随盘中波动。

### ② 取价口径：基准跟"国内收盘时刻"走

一句话原则：**基准 = 国内对应品种最近一次收盘时刻的价**，不跟着外盘品种自己的收盘时刻走。

| 情形 | 取法 |
|---|---|
| 外盘在"国内收盘时刻"正在交易 | 取那一刻的价（一般商品 23:00、有色 01:00、贵金属 02:30） |
| 外盘在那个时刻**已经收盘** | 用它自己的收盘价顶上（如日橡胶 14:50 收盘，而节点是 15:00） |
| 外盘在那个时刻**还没开盘** | 取"该时刻之后的**第一笔**"（如美原糖 15:30 才开盘 → 取 15:30 那一笔），保证时间跨度与其他品种一致 |

两个特殊品种因此有专门口径：

- **日橡胶**：日盘 14:50 收盘，`day` 档取**当天日K那根的收盘价**（= 14:50 的价）。该品种成交极稀疏，分时表在收盘前常已无成交，按"取节点前最后一笔"会取到 14:11 的价。
- **美原糖**：15:30 才开盘，白档（10:15 / 11:30 / 15:00）它**都没有价**，取"该时刻之后的第一笔"。

原油是个特例：国内燃油/沥青 23:00 收盘、国内原油 02:30 收盘，两组参考点都要，所以**夜盘档显示两行原油**（白档只显示一行）。

### ③ 「起始时间」列：显示实际取到那一笔的时刻

时间机制比较复杂，所以把起始时间单独放在**最后一列**，并且显示的是**实际取到那一笔价**的时刻（而不是标称的整点档位）。

举例：某品种在 15:00 那一分钟没有成交，实际取的是 14:46 的那一笔 —— 那就直接显示 `14:46`，拿这个时刻去分钟图上反查就能对上。**不加任何小标**，看着时间就明白。

只有两种情况会额外标注：
- 该行用的是**云端落盘值**（三条实时路都没拿到）→ 标「缓存」
- 发生**换月** → 第 ⑧ 节

### ④ 三条实时路 + 逐层兜底

```
① 腾讯行情 qt.gtimg.cn      浏览器直连     滞后几秒        ← 16 个品种主路
② 新浪行情（经 Cloudflare）  准实时         滞后 8-20 秒    ← 6 个品种主路
③ 新浪分时表末根             浏览器直连     滞后 ≈1 分钟    ← ② 挂掉时自动接管
（④ 云端 data.json 落盘值 —— 三条都没拿到时兜底，行上标「缓存」）
```

**没有任何延时源**：腾讯 `fuHO`（延时 10-15 分钟）与 TradingView（延时 10-20 分钟）已全部剔除 —— 只看当下的价。

**③ 的作用**：新浪那条主路依赖 Cloudflare 中转，中转本身是个外部依赖。有了 ③，中转出问题时那 6 个品种会自动切到同源的新浪分时表（直连、不用中转），数字仍然是当下的价 —— 从"单点故障"降级成"性能更好的首选"。

### ⑤ 行情源选择（均为实测）

| 行情源 | 浏览器能直连吗 | 覆盖 | 定位 |
|---|---|---|---|
| 腾讯行情 `qt.gtimg.cn` | ✅ 可以（跨域全开） | 16 个品种 | 主力实时源 |
| 新浪行情 `hq.sinajs.cn` | ❌ 不行（防盗链 + 无跨域头） | 6 个品种：原糖 / 棉花 / 马棕油 / 铁矿 / 日橡胶 / 美燃油 | 准实时（滞后 8-20 秒），必须中转 |
| 新浪分时表 `stock2.finance.sina.com.cn` | ✅ 可以（无 Referer 校验） | 同上 6 个 | 接管腿（滞后 ≈1 分钟） |

新浪快照那 6 个品种，其他家都没有准实时数据，所以必须想办法把新浪"接"过来 —— 这就是 Cloudflare 中转的由来。

### ⑥ Cloudflare 中转：为什么、怎么做、为什么做了两条

**问题**：新浪行情接口有防盗链——只允许"从新浪自家页面发来的请求"（浏览器请求时会带一个 `Referer` 头标明来源页面，新浪会校验它是不是自家域名）；同时接口不开放跨域许可（没开 CORS，网页拿不到返回内容）。浏览器直接请求会被挡死。

**思路**：用一个"中间人"替浏览器去请求新浪——它加上新浪认可的 `Referer`，把数据原样转回来，并顺手打开跨域许可。这个中间人就是 **Cloudflare 的免费服务**（无需服务器、全球节点、额度足够个人用量）。

**落地与演进（两代）**：

1. **第一代：Cloudflare Worker**（地址形如 `*.workers.dev`）
   写了一个约 25 行的转发：请求 `hq.sinajs.cn` 时带上 `Referer: https://finance.sina.com.cn`，返回时加上 `Access-Control-Allow-Origin: *`。
   上线后发现一个坑：`workers.dev` 域名在国内不少网络下**直连会被重置（连接被掐断）**——电脑挂着代理能用，手机出门（无代理）就废了。

2. **第二代：Cloudflare Pages 直连通道**（地址形如 `*.pages.dev`）
   实测发现 Cloudflare **Pages** 的 `pages.dev` 域名国内可以直连。于是用 Pages 的"高级模式"（`_worker.js`）又部署了一个**同款转发服务**，作为手机等无代理场景的直连通道。

   现在前端同时配置两个地址，按序尝试：**先连 Pages（普适，手机也能用）→ 失败切 Worker（有代理时的兜底）**，单条通道 4 秒超时自动切换。

3. **两条都连不上也不慌**：那 6 个品种自动改用新浪分时表接管（见 ④），其余品种不受影响。

<details>
<summary>展开：中转服务的核心代码（Worker 与 Pages 高级模式用同一份）</summary>

```js
export default {
  async fetch(request) {
    const cors = {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Methods': 'GET, OPTIONS',
      'Cache-Control': 'no-store',
    };
    if (request.method === 'OPTIONS') {
      return new Response(null, { status: 204, headers: cors });
    }
    const list = new URL(request.url).searchParams.get('list') || '';
    if (!/^[A-Za-z0-9_,\.]{1,500}$/.test(list)) {
      return new Response('bad list', { status: 400, headers: cors });
    }
    const resp = await fetch('https://hq.sinajs.cn/list=' + list, {
      headers: {
        'Referer': 'https://finance.sina.com.cn',
        'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/122 Safari/537.36',
      },
    });
    const buf = await resp.arrayBuffer();
    const h = new Headers(cors);
    h.set('Content-Type', 'application/javascript; charset=GBK');
    return new Response(buf, { status: resp.status, headers: h });
  },
};
```

</details>

### ⑦ 云端慢的时候：页面自动补档

GitHub Actions 有 26-36 分钟的排队延迟，所以「10:15 档」的起始价可能要到 10:40 才落盘 —— 而 10:30 就要开盘了。

页面的处理：发现云端档位落后时，自己翻新浪分时表把当前档的基准价算出来补上。**算出来的值与云端逐位一致**（同源、同口径），所以**不加任何标记**；`data.json` 一更新就自动切回云端值。

### ⑧ 换月检测

主连换月时，老的参考价与新合约的行情混在一起，涨跌幅会失真（例：某品种老合约 4.834、新合约 4.596，页面显示假跌 -4.9%，实际约 -1.3%）。

检测判据：**起始价跑出当段分时表的价格区间，且明显偏离当前合约的昨结算**。

- 原理：同一段分时表必然是同一个合约，起始价正常时要么取自该表（必在区间内）、要么是明确的特判来源；只有"跨换月线被继承钉住的老合约价"会同时满足"跑出区间 + 明显偏离昨结算"。
- 双阈值分级：偏离 ≥ 2.5% 自动修正；1.5%~2.5% 只记录嫌疑、不动数值（避免把"跨时段继承的正确值"改错）。
- 修正动作：起始价 := **昨结算**（与行情软件口径一致），「起始时间」列显示「**换月**」。
- 备用开关：`fetch.py` 顶部的 `ROLLOVER_OVERRIDE`（强制按换月处理）、`ROLLOVER_EXCLUDE`（明确排除的品种）。

### ⑨ 上证指数临时行（商品开盘前的参考）

国内商品 10:30 / 13:30 开盘前，需要参考 A 股对 10:15 / 11:30 的涨跌来预判。所以页面只在特定窗口显示"上证指数"这一行：

| 窗口 | 显示时段 | 对比基准 |
|---|---|---|
| 10:15 档 | 10:15 – 10:30 | 当天 10:15 的价（从当日分时数据回溯取点） |
| 11:30 档 | 11:30 – 13:30 | 当天 11:30 上午收盘价（11:30–13:00 休市显示 0.00%，13:00 后随行情跳动） |

其余时间不显示该行，也不产生任何网络请求。数据同样走腾讯行情接口、浏览器直连。

### ⑩ 电脑端 EXE（桌面出图工具）

除网页外，项目还有一个配套的 Windows 小工具（**不随本仓库分发**）：双击运行，几秒内生成一张与网页同款的表格图（PNG）并自动打开——适合快速截图存档、发群里对照。定位上：网页管"随时随地看实时"，EXE 管"一键出图留档"。

实现思路与网页端同源、但链路更简化：

- **起始价仍复用云端**：启动时拉 GitHub Pages / jsDelivr 上的 `data.json`（与网页同一份数据、同一套档位判定），两个源取较新的一份，避免 CDN 缓存拿到旧数据。
- **最新价改为本机直取**：桌面程序不受浏览器那两条限制（请求头可自由设置、跨域限制也不存在），直接请求新浪行情（带上 Referer 即可）一次拉齐 22 个品种——**连 Cloudflare 中转都不需要**，中转本来就是只给浏览器绕限制用的。
- **本地绘制图片**：用 Python + Pillow 计算涨跌幅并绘制表格（名称左对齐、数值右对齐，红涨绿跌，版式与网页一致），文件名按生成时间命名。
- 程序用 PyInstaller 打包为单文件，双击即用，无需安装任何环境。

### ⑪ 点品种名看全屏 K 线（`k/` 目录）

表格里每个品种名都可点，打开的是**新浪原版全屏 K 线**：悬停读价、分时/日K/周K/5-60 分钟切换、MACD/BOLL/RSI 切换、画线工具都在，观感与在新浪行情页点右上角「全屏查看」完全一致。

**为什么要在自己站上存一份**：新浪的全屏是纯前端行为（把图表 DOM 搬进一个 `z-index:8888` 的 fixed 遮罩），没有 URL 参数能触发；跨域 iframe 又碰不到它里面的按钮。只有把行情页 HTML 同源托管，注入的脚本才点得到那一下。

实现（文件为 `k/<代码>.html`，代码统一小写，如 `k/cl.html`、`k/gc.html`）：

| 步骤 | 做法 |
|---|---|
| 1 | 抓 `finance.sina.com.cn/futures/quotes/<代码>.shtml`，按页面 meta charset 解码后统一转 UTF-8 |
| 2 | 把页面里所有 `hq.sinajs.cn` 改写为自建中转（浏览器直连必 403，见 ⑥） |
| 3 | 注入脚本：劫持 `document.createElement` 的 `script.src`，另用 MutationObserver 兜底改写已插入的 script |
| 4 | 轮询到 `.kke_cfg_fullscreen` 后自动点一次全屏；移除「发现新版本」浮层；`html.__fs_wait` 把首屏藏起来，全屏完成再显示，避免闪一下整页 |

休市品种（马棕油、LME 金属）的报价长期是 `--`，所以触发条件是「控件出现就点，最多等 3 秒」，不等报价。

**新增品种**：抓页面 → 按上面四步注入 → 存成 `k/<小写代码>.html` → 在 `index.html` 的 `KLINE_URL` 里补一行 `'hf_XXX':'k/xxx.html'`。

## 数据流总览

```
云端（GitHub Actions，每天 14 轮定时）
    fetch.py ──抓起始价──▶ data.json
                              │
浏览器打开网页 index.html ◀────┘（读起始价）
    │
    ├─ ① 腾讯行情直连（16 品种，实时，15 秒轮询）
    ├─ ② 新浪行情 ←── Cloudflare 中转（6 品种，准实时 8-20 秒）
    │        主通道：sina-hq.pages.dev（国内可直连）
    │        备通道：*.workers.dev（需代理，兜底）
    └─ ③ 新浪分时表直连（6 品种，② 挂掉时自动接管，滞后 ≈1 分钟）
              │
              ▼
    浏览器本地计算涨跌幅（最新价 − 起始价）→ 渲染表格（红涨绿跌）
```

- 打开即用本地缓存秒开，再补齐云端数据（不闪旧价）
- 切到后台自动暂停轮询省流，切回来立即刷新
- 云端档位落后时，页面自己用分时表补算当前档（⑦），`data.json` 一更新自动让位

## 文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 展示页（单文件：样式 + 全部前端逻辑） |
| `fetch.py` | 云端抓取起始价，写出 `data.json` |
| `.github/workflows/fetch.yml` | 定时任务配置（每天 14 轮，见下表） |
| `data.json` | 数据文件（由任务自动生成、自动提交） |
| `k/<代码>.html` | 各品种的新浪行情页镜像（22 个，小写命名，如 `k/cl.html`）；点表格品种名打开，自动进入全屏 K 线（见 ⑪） |

`data.json` 每行除价格外还带两个说明字段：`ref_actual`（该行基准价**实际取自哪一笔**的时刻）、`gap_min`（与标称档位节点差几分钟），供页面「起始时间」列显示与事后核对。
